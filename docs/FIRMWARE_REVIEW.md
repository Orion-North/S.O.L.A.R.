## Fix first

1. **Authenticate or disable ArduinoOTA** (`solar_main.ino:2416`). The web updater uses `SOLAR_OTA_PASSWORD`, but ArduinoOTA starts without `setPassword()`. The installed ArduinoOTA implementation accepts an update without authentication when its password is empty. Apply the configured password before `begin()`, and skip ArduinoOTA initialization/handling when updates are disabled. Both update paths should also disable motor outputs before flash writes; currently their start callbacks only select stand, leaving torque/calibration active.

2. **Make the command watchdog effective in calibration and RL** (`solar_main.ino:1416`, `:1438`, `:1824`). On timeout, the task changes mode to idle, but `calibrationMode` takes precedence and continues holding/interpolating manual targets. `/test` can therefore continue moving after the timeout. Also, any `/ping` refreshes the same timestamp as an RL action; a live heartbeat can keep an old RL target active indefinitely. Separate connection heartbeat from fresh motion/action timestamps and explicitly define timeout behavior for calibration, RL, and continuous emotes. Continuous wag/curious/play_bow currently have no timeout.

3. **Abort test sequences on stop/torque changes** (`solar_main.ino:1205`, `:1241`). `smartWait()` services requests, but the sequence never checks cancellation. `/torque?state=0` disables outputs, then later iterations mark the next leg's outputs enabled. If torque is enabled again, the old sequence can resume interfering with the new command. An estop followed by clear/re-enable during the sequence has the same problem. Use a cancellable state machine with a generation ID; a stop or replacement command must invalidate the old sequence. This also avoids nested `server.handleClient()` calls from within the active sequence.

4. **Handle failed PCA9685 writes** (`solar_main.ino:422`, `:443`, `:1739`). `pwm.begin()` and `pwm.setPWM()` return success/failure, but both are ignored. `lastServoPulse` is updated even when a write fails, suppressing retries for unchanged targets. Failed stop writes have no retry path either. Cache only successful writes, expose an actuator fault, and use bounded retries/recovery. Consider an independently controlled PCA9685 OE signal for a hardware output-disable path if wiring allows it.

5. **Validate numeric input before committing state** (`solar_main.ino:336`, `:1075`, `:2249`, `:2268`, `:2378`). The installed `String::toFloat()` calls `atof`: malformed text becomes zero, while `nan` can survive `constrain()`. Nonfinite settings or targets can reach float-to-integer PWM conversion. Parse strictly with an end pointer, require `isfinite()`, validate count/range, and reject the whole request on failure. RL CSV parsing also accepts extra values after the twelfth. `/cmd` updates velocity and cancels charge rest before checking whether mode is valid; validate first so a rejected command changes nothing.

6. **Commit motion state atomically** (`solar_main.ino:1061`, `:1403`, `:1672`, `:1915`, `:2249`). The gait computes from a snapshot, then writes targets leg by leg; a newer HTTP command can be overwritten by a stale gait iteration. Phase variables are read/written outside the lock by gait while HTTP resets them under the lock. Mapping IDs and offsets are also read without the same lock used for settings writes. Make gait own phase state, snapshot configuration together, and commit a full target frame only if its command generation is still current. Recheck charge-rest state and start time under the lock before powering down; the current cached flag can turn off torque after another request has cancelled rest.

## Timing and movement improvements

7. **Use a fixed gait schedule and bounded catch-up** (`solar_main.ino:1399`, `:1594`, `:1650`, `:1676`). `vTaskDelay(20 ms)` adds execution time to each cycle, so actual frequency is below the advertised 50 Hz. Use `pdMS_TO_TICKS()` and `vTaskDelayUntil()`, as the IMU task already does. Bound interpolation `dt` after stalls so recovery cannot produce a large angle jump, and wrap gait phase with `phase -= floorf(phase)` rather than subtracting one only once. Publish measured cycle time/deadline misses instead of a constant `gait_hz`.

8. **Preserve fractional servo angles** (`solar_main.ino:1153`). Arduino `map()` takes `long`, so `finalAngle` loses its fractional component before conversion. Use floating-point pulse interpolation and round once at the end. The configured 530-count span across 180 degrees provides approximately 0.34 degrees/count, but the current mapping discards sub-degree commands. Retain the deadband initially and measure whether it needs adjustment.

9. **Bound shared-I2C blocking** (`solar_main.ino:428`, `:1717`). PWM holds the global state mutex through I2C. The installed TwoWire default transaction timeout is 50 ms, longer than a gait cycle, and shared-bus IMU/diagnostics can add contention. Set an explicit, measured bus timeout and record errors/lock latency. A single task owning actuator I2C can simplify ordering, provided stop requests retain priority and stale writes remain prohibited.

10. **Separate camera transfers from control HTTP** (`solar_main.ino:1830`, `:1870`). `/capture` sends the complete JPEG synchronously in the same server that handles `/estop` and commands. The installed WiFiClient writer can wait repeatedly for socket writability; a slow reader delays control. A separate camera server/task with bounded transfer lifetime and frame ownership would isolate this. Measure command/estop latency with camera on, off, and a deliberately slow receiver. Merely adding an outer-loop deadline does not bound an individual blocking `write()`.

## Configuration and longer-term cleanup

11. **Validate and persist settings without long motion locks** (`solar_main.ino:2249`). NVS writes occur while `stateMutex` is held, pausing gait and IMU publication. Duplicate leg-set assignments are accepted, allowing multiple legs to overwrite the same motor targets. Require a permutation of 1–4, finite bounded offsets, and preferably torque-off for mapping changes. Persist a versioned record outside the motion lock and check save success. Live offsets and wiring need physical validation.

12. **Reduce hot-loop allocation and repeated math** (`solar_main.ino:1408`, `:1609`). Replace internal mode Strings with an enum and convert at the API boundary. Calculate sine/cosine once per diagonal pair rather than once per leg, use float math variants where appropriate, and keep phase bounded. These are secondary optimizations: measure cycle time and heap minimum/largest free block before introducing lookup tables or complex batching.

13. **Make builds and startup faults reproducible** (`platformio.ini:15`, `solar_main.ino:1697`, `:1700`, `:2437`). Pin the platform and unversioned Adafruit dependency to tested versions. Check mutex/task creation and driver initialization before accepting torque commands. Brownout detection is explicitly disabled; evaluate restoring it after measuring supply transients rather than masking power faults.

Existing good choices worth retaining: single-burst IMU reads, dedicated IMU sampling, cached solar readings, binary telemetry, servo pulse deadband, and the safety recheck before PWM writes.

## Validation to accompany changes

Use host-level checks for strict parsing and state transitions, then bench tests with the robot supported: lost command stream during calibration/RL, estop during test sequence, cancel charge rest at its deadline, missing/reconnected PCA9685, settings under telemetry load, and slow camera receivers. Measure gait period/jitter, worst-case stop latency, I2C failures, and heap/stack headroom. A simulator API benchmark does not establish physical firmware timing.
